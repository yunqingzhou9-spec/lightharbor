# 拾光 · LightHarbor

**让底片，回到各自的位置。**

一个在 Mac 本地运行的照片与延时摄影整理工具：先预览文件夹结构，自由调整，再确认复制。照片不上传；复制保留原件，清理功能须单独预览确认。

当前发布：**Mac 1.3.4** · **Windows 1.4.1 预览版**。

[下载 Windows x64 预览版](https://github.com/yunqingzhou9-spec/lightharbor/releases/tag/v1.4.1-windows-preview)：完整解压后运行 `Start-LightHarbor.cmd`，无需安装 Python，需要 WebView2 Runtime 与 .NET Framework 4.8。Windows 暂不支持 Apple Vision 景物识别，部分 RAW/HEIC 预览受限；尚未完成 Windows 实机端到端验证。

[下载已发布 Mac 版](https://github.com/yunqingzhou9-spec/lightharbor/releases/latest) · [使用说明](macos/使用说明.txt) · [反馈问题](https://github.com/yunqingzhou9-spec/lightharbor/issues)

## 安装

- macOS 13 Ventura 及以上，Apple 芯片 / Intel 通用二进制。
- 解压 Mac 版 ZIP，把 **拾光.app** 放到 Applications 或你喜欢的工具文件夹，双击启动。
- 已包含 Python 和图片读取组件，不需要安装开发环境。
- 应用在独立 Mac 窗口中展示工作台，无需打开 Safari 或 Chrome；支持调整窗口、原生文件夹选择和复制粘贴。

**签名说明：** 当前版本有本地临时签名，但没有 Apple Developer ID 签名和公证。macOS 可能阻止首次打开。确认来源是本仓库 Release 后，可按系统提示在“系统设置 → 隐私与安全性”选择“仍要打开”。不要关闭系统安全保护。受单位管理的电脑可能限制未公证应用。

通用架构与最低系统版本属于构建目标；实际测试范围以每个 Release 的说明为准，不代表已在每种 Mac 和系统版本上实测。

## 能做什么

- 按日期整理，自动寻找拍摄间隔规律的延时序列。
- 同一次拍摄的 RAW / JPEG / 可靠关联的 XMP、AAE 一起调整，保存时分格式子目录。
- 两种目录方式：日期 → 拍摄组 → 格式；日期 → 地点 / 景物 → 拍摄类型 → 拍摄组 → 格式。
- 目录导航、可点击的路径层级、缩略图、多选、拍摄组首 / 中 / 尾抽样。
- 改名、移动到其他拍摄组、新建组、拆分、合并、排除、恢复，以及最近 12 步撤销。
- 本地 GPS 坐标分区及 Apple Vision 景物分类，均不依赖云端服务。
- 最终复制前检查来源变化、空间和同名冲突；复制后做 SHA-256 校验。

## 按日期清理存储卡

扫描后点击“清理存储卡…”，勾选日期，再核对备份并展开完整清单。仅允许删除在另一个磁盘卷上存在内容完全一致备份的照片；关联 RAW / JPEG / XMP 必须全部备份完整。文件名相同不能作为删除依据。确认执行前再次核验，文件变化会阻止删除，过程保留清理日志。视频和未关联文件不在本次清理范围内。

## 使用流程

1. 选择来源（如存储卡的 DCIM）和独立的保存目录，两者不能相同或互相包含。
2. 扫描生成预览。此时不会创建照片目录或复制文件。
3. 核对目录、延时组和照片归属，按需调整。搜索和筛选不等于排除文件。
4. 点击“下一步：检查并确认”，再核对检查结果。
5. 点击“确认无误，开始复制”后才写入目标。

```text
2026/
└── 2026-05-03/
    └── 延时_2026-05-03_17时36分36秒至17时44分20秒/
        ├── RAW/
        │   ├── DSC0001.ARW
        │   └── DSC0001.xmp
        └── JPEG/
            └── DSC0001.JPG
```

延时名称来自照片拍摄时间。跨天时写出结束日期，整组归入开始日期；同名序列追加编号。自动名称随组内有效起止时间调整，手动命名后保留。每段延时一个组，不为每张照片单独建目录。

## 需要了解的边界

- 延时检测是辅助判断，初始标为“待确认”。默认至少 30 次拍摄、20% 间隔容差。RAW + JPEG 配对后算一次拍摄。
- 仅可靠的 EXIF 原始拍摄时间参与延时判断；同来源目录、同相机、规律间隔 1–3600 秒。支持少量漏拍；普通规律拍照也可能入选，变间隔、短于 1 秒、跨来源目录的序列可能漏掉，可手动调整。
- 不可靠时间会标记待确认；文件修改时间可用于归档，但不冒充可靠拍摄时间。相机时间不做时区纠正。
- 推荐的拍摄组模式中，地点和景物用于筛选，不新增目录层级。地点 / 景物模式才按勾选项分层。整段延时不会因不同画面标签拆散。
- 地点为 GPS 0.02 度坐标分区，不是城市或景点名；景物为系统粗分类。没有定位或把握不足时保留待确认状态。
- RAW 解码取决于 macOS 支持。无法生成缩略图时仍可复制原文件。
- 关联文件必须匹配可靠；不明确的 XMP / AAE 单独保留。Live Photo 视频不凭同名配对。
- 当前支持拍摄组改名及照片移组，不支持任意路径输入或逐层改日期 / 地点目录名。

## 文件保护与退出

普通复制不移动、删除或修改来源。独立的“清理存储卡”功能仅在预览和输入确认文字后永久删除原片，不经过废纸篓。同名冲突通过关联编号解决，不覆盖已有文件；全库内容去重不在本版范围内。副本保留文件修改时间，未承诺保留资源叉、扩展属性或 Finder 标签。

正常停止会清理本次未完成副本并保留完整副本。强制结束或断电仍可能留下不完整副本，请核对结果。目标 `.整理记录` 中有完整 JSONL 清单，界面显示全量统计；全部处理明细默认折叠，展开后每次加载 200 条，可查看全部记录。

**计划保存在本机。** 可在“恢复之前的整理任务”中恢复文件夹调整和复制范围。恢复后重新核对已有副本，手动选择处理方式，再确认复制。重新扫描会建立新任务。关闭应用窗口会提示退出，并安全停止活动任务。

## 隐私

仅监听 `127.0.0.1`，操作需要随机访问令牌及最新计划版本。无远程脚本，无照片上传，不调用收费 AI 接口。不要分享含访问令牌的启动地址。反馈问题时请遮挡个人路径、照片内容、精确 GPS 及访问令牌。

## 从源码运行与构建

源码模式需要 macOS、Python 3.10+，图片组件首次编译需要 Xcode Command Line Tools。

```sh
xcrun swiftc -O MediaProbe.swift -o media-probe
python3 app.py
python3 -m unittest -v test_app.py test_planner.py
```

也可双击 `启动整理工具.command`。完整应用打包见 [macOS 构建说明](macos/BUILD.md)。

| 文件 | 用途 |
|---|---|
| `planner.py` | 拍摄组识别、路径规划、可撤销调整 |
| `app.py` | 元数据扫描、检查、复制、本地服务 |
| `index.html` | 中文工作台（桌面版内嵌 WebKit，源码模式可用浏览器） |
| `MediaProbe.swift` | macOS ImageIO / Vision 读取、预览、分类 |
| `mac_entry.py` | 原生应用的后台服务与安全退出协议 |
| `macos/Launcher.swift` | 原生启动窗口和应用生命周期 |

构建工具及运行环境的第三方许可证随应用附带。正式发布包不包含个人照片、整理计划、私有开发记录或调试凭据。

1.2.0：复制范围与任务恢复
• 默认全复制；“选择要复制的文件夹”支持多选上级日期或拍摄组。
• 勾选照片后点“复制所选照片”；继续选其他照片可“加入本次复制清单”。关联 RAW / JPEG / XMP 一起纳入，格式仍分开存放。点击“恢复全复制”取消范围限制。
• 搜索、筛选、左侧合并拍摄组的勾选不改变复制范围。范围数量在预览顶部显示。
• 默认在所选目标目录及其子目录按文件名（含扩展名）快速查重，不读取照片内容。同名不保证内容一致；可在更多设置中选择完整内容校验。
• 发现副本后必须手动选择“跳过匹配文件”或“全部再复制一份”，再点最终确认。不覆盖文件，不会默认勾选跳过。
• 任务保存在 ~/Library/Application Support/LightHarbor/tasks，仅含本机路径、整理计划和校验信息，不上传、不随安装包分享。
• 支持文件级续复制：恢复任务后重新核对并确认；完成的副本可选择跳过，中断的文件需完整重复制，不支持单个文件内部按字节续传。
• 恢复使用原来的来源与目标路径。磁盘离线或来源内容改变时停止并提示。外部移动过的归档副本可能需重新扫描。

1.3.0：导入状态、暂停与完成记录
• 扫描后按日期显示未整理、已有副本、需要核对的文件数，点击数量查看明细。1.3.1 默认显示同名匹配状态，明确标注未核对内容；选择完整内容校验时才读取文件。
• 复制时显示传输量、已处理文件数、平均传输速度和估算剩余时间。速度和时间包含校验等待，实际耗时受磁盘影响。
• “暂停复制”保留本次任务，点击“继续复制”接着处理；“停止”则结束本次执行，下次通过恢复任务重新核对。暂停状态退出也会安全停止。
• 完成页分别展示新复制、确认跳过、失败和未处理数量。展开实际归档目录，可在访达中打开。未连接的磁盘会提示接回。
• 失败照片可以重新核对再复制；关联文件一起核对，已有副本仍须手动确认跳过。
• 新版的历次执行记录保存在本机任务目录的 history 子目录，按拍摄日期或整理日期搜索，支持分页查看全量明细。旧版原始整理记录仍保留在归档目录的 .整理记录 中。

1.3.1：快速查重与校验复用
• 默认仅匹配文件名和扩展名（忽略大小写），发现同名文件后仍须手动确认是否跳过；大小不同会提示。
• 完整校验结果在本次运行中复用，文件身份、大小或修改状态变化后重新校验；重启后不沿用内存缓存。
• 新文件边复制边计算校验值，复制后核对目标文件，减少复制前额外读取来源的次数。
